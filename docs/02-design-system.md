# 02 — نظام التصميم

> ملف واحد للتنسيق: `public/static/style.css` (≈73 كيلوبايت، 17.7 كيلوبايت
> مضغوطة). لا Tailwind، لا SASS، لا CSS-in-JS. المتغيّرات الأصلية
> (Custom Properties) تلعب دور نظام الرموز (design tokens).

---

## 1. لماذا CSS واحد يدويّ؟

- **طلب شبكي واحد** يُخزَّن سنة كاملة (`max-age=31536000, immutable`).
- **صفر جافاسكربت** لتوليد الأنماط → لا حجب للرسم.
- Tailwind كان سيضيف خطوة بناء ومئات الأصناف المولّدة، مع فقدان أهم شيء
  في هذا المشروع: **التعليقات العربية التي تشرح سبب كل رقم**.

---

## 2. الرموز (Tokens) — المصدر الوحيد للحقيقة

كلها في `:root` أعلى الملف. **لا تكتب لونًا صريحًا في أي مكان آخر.**

### السطح — سُلَّم الأونيكس
```css
--noir:     #080706    /* الخلفية العميقة */
--onyx:     #0f0d0b
--onyx-mid: #16130f
--onyx-elev:#1e1a15    /* البطاقات */
--onyx-high:#272117    /* الحالات المرتفعة */
```

### الذهب — سُلَّم واحد فقط
```css
--gold:      #c5a059   /* الأساس */
--gold-lite: #e2c68e   /* النصوص الذهبية */
--gold-deep: #a67c37
--bronze:    #85642e
--gold-grad: linear-gradient(135deg,#a67c37,#c5a059 32%,#e2c68e 62%,#c5a059)
--gold-text: linear-gradient(120deg,#e2c68e,#c5a059 50%,#e2c68e)
```
ودرجات شفافية جاهزة للخطوط الشعرية والهالات:
`--gold-04 · --gold-08 · --gold-14 · --gold-22 · --gold-38`

> **قاعدة:** كل خط فاصل في الموقع هو `1px solid var(--gold-08)` أو
> `var(--gold-14)`. لا تستخدم رماديًا أبدًا — الرمادي البارد يقتل الإحساس
> الفخم على خلفية دافئة.

### النص — لؤلؤ دافئ، لا رمادي بارد
```css
--pearl:       #f6f0e3
--pearl-soft:  rgba(246,240,227,.86)
--pearl-mute:  rgba(246,240,227,.74)
--pearl-faint: rgba(246,240,227,.56)
```

### أنصاف الأقطار والارتفاع والحركة والإيقاع
```css
--r-sm:10 --r-md:16 --r-lg:22 --r-xl:28 --r-2xl:36 --r-pill:999px
--sh-sm/-md/-lg/-gold   --inset-hi
--ease: cubic-bezier(.22,1,.36,1)   --t-fast:.28s   --t-mid:.45s
--hdr-h:60px  --nav-h:66px
--sp-sec:68px  --gutter:18px  --maxw:1240px
```
وتتوسّع عند نقاط الكسر:
```css
@media (min-width:768px){  --sp-sec:96px;  --gutter:32px; --hdr-h:76px }
@media (min-width:1024px){ --sp-sec:120px }
```

## 3. 🔴 الطباعة العربية — أهم قسم في هذا الملف

### الخطأ الذي وقعنا فيه فعلًا وكلّفنا شكوى مباشرة من العميل

استخدمنا `line-height: 1.16` للعنوان الرئيسي — وهي قيمة **لاتينية سليمة
تمامًا**. النتيجة: **تشابك الخطوط** (`تشابك الخطوط` بنص العميل).

**السبب التقني الدقيق:**
خط Amiri العربي فيه ثلاث طبقات رأسية لا توجد في الخطوط اللاتينية:
1. **صواعد طويلة**: ل، ك، ط، ظ، أ
2. **نوازل عميقة**: ج، ح، خ، ع، غ، ي، ن
3. **التشكيل فوق خط الحد الأعلى** (فتحة، شدّة، مدّة) — وهذا ما لا يحسبه
   أي مطوّر آتٍ من الويب اللاتيني.

مجموع الثلاثة يعني أن الصندوق البصري للسطر العربي **أطول بنحو 25٪** من
نظيره اللاتيني بنفس `font-size`.

### الحدود الدنيا الآمنة — لا تنزل عنها

| العنصر | الحد الأدنى | ملاحظة |
|---|---|---|
| `h1` | **1.44** | كان 1.16 وتشابك |
| `h2` | **1.42** | |
| `h3` | **1.46** | |
| `h4` | **1.50** | أصغر حجمًا ⇒ يحتاج نسبة أكبر |
| نص أساسي | **1.42** | |

**الدليل المقيس:** المسافة بين خطي العنوان الرئيسي انتقلت من
**35.96 بكسل → 44.64 بكسل** بعد التعديل.

### 🔴 تباعد الأحرف: العربية خط متّصل

كان `.eyebrow { letter-spacing: .24em }` — وهي حيلة فخمة معروفة في
التصميم اللاتيني. في العربية **تمزّق وصلات الحروف** وتجعل الكلمة تُقرأ
حروفًا منفصلة.

```css
/* ❌ .24em — تمزّق الوصلات */
/* ✅ الحد الأقصى المسموح: */
letter-spacing: .06em;
```

### الخطّان
```css
--f-display: 'Amiri', 'Playfair Display', Georgia, serif;  /* العناوين */
--f-body:    'Tajawal', system-ui, -apple-system, sans-serif; /* النص */
```

### `HeroPic` — المكوّن الذي حلّ أكبر شكوى بصرية

```tsx
<picture>
  <source media="(max-width:767px)" srcset={/* تركيب طولي 900×1600 */} />
  <img src={/* تركيب عرضي 1600×893 */} />
</picture>
```

**المشكلة التي حلّها:** صورة 16:9 داخل إطار هاتف 390×926 لا يبقى منها إلا
شريط رأسي ضيّق — والموضوع (الدلّة) يقع **خارج** هذا الشريط، فيرى المستخدم
ضبابية خلفية فقط. شكوى العميل الحرفية: «صورة ما تعرفها شي». الحل ليس
تحسين جودة الصورة بل **تركيب طولي مستقل للجوال**.

التفصيل الكامل والدليل في [`07-decisions.md`](./07-decisions.md#قرار-3).

## 6. القائمة السفلية (Sheet) — من صفحة إلى قائمة

شكوى العميل: «كلام هدرة… هذي صفحة مو قائمة».

**السبب:** كتلة شعار 44 بكسل + بطاقتان مكدّستان 76 بكسل = نحو **180
بكسل** قبل ظهور أول رابط، ثم 9 صفوف كاملة بأسطر وصفية، ثم عنوانان
فرعيان، ثم 7 شرائح مدن، ثم فوتر من 3 أسطر.

**الحل:** صف هوية واحد (40 بكسل) + شبكة **3 أعمدة × بلاطات 62 بكسل** +
صف ختامي واحد.

| القياس | قبل | بعد |
|---|---|---|
| ارتفاع القائمة | 740 بكسل | **390 بكسل** |
| من ارتفاع الشاشة | 88٪ | **46٪** |
| زر واتساب | 172×76 | **90×36** |
| زر الاتصال | 172×76 | **80×36** |

## 7. قواعد HTML الدلالي (مُطبَّقة في كل العروض)

- استخدم `<header> <nav> <main> <section> <article> <aside> <footer>`.
  `<div>` فقط عند عدم وجود وسم دلالي مناسب.
- كل قسم رئيسي له `id` ذو معنى: `#services` لا `#div1`.
- أسماء الأصناف تصف **الوظيفة** لا الشكل: `.service-card` لا `.box`.
- التعشيش سطحي — لا أغلفة زائدة.
- **صفر إيموجي، صفر خطوط أيقونات.** كل الأيقونات SVG سطري من
  `src/icons.tsx`.

## 8. الحركة

قاعدة واحدة تحكم كل حركة في الموقع:

> **حرِّك `transform` و `opacity` فقط.**

لأن هاتين الخاصيتين تُنفَّذان على خيط المُركِّب (compositor) دون تخطيط
(layout) ولا رسم (paint) → إزاحة تخطيط تراكمية **CLS = 0**.

وكل حركة محاطة بـ:
```css
@media (prefers-reduced-motion: reduce){ animation: none }
```

طبقات البطل السينمائي الخمس وتكلفتها في
[`05-performance.md`](./05-performance.md).

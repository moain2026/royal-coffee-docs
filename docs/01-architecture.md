# 01 — البنية المعمارية

> الهدف من هذا الملف: أن يفهم أي مبرمج **كيف يعمل الموقع من الطلب حتى
> HTML**، وأن يفهم **لماذا** اختيرت هذه البنية تحديدًا، قبل أن يلمس سطرًا
> واحدًا من الكود.

---

## 1. الصورة الكبيرة في سطر واحد

الموقع **تطبيق Hono واحد** يعمل على الحافة (Edge)، يُصدِّر HTML كاملًا من
السيرفر لكل صفحة، ولا يوجد فيه أي إطار عمل واجهات (لا React، لا Vue، لا
Next). الجافاسكربت في المتصفح **ملف واحد** مهمته التزيين والتفاعل فقط —
لو تعطّل، الموقع كامل يبقى قابلًا للقراءة والاستخدام.

```
طلب المتصفح
    │
    ▼
Cloudflare Pages Worker  /  Vercel Edge Function
    │
    ├── /static/*  ──────────►  ملف ثابت (يخدمه المنصّة نفسها، لا يمر على الكود)
    │
    └── أي مسار آخر
            │
            ▼
        src/index.tsx      ← جدول المسارات (18 معالجًا)
            │
            ├── يطابق المسار ويستخرج البيانات من  src/data.ts / src/cities.ts
            │
            ▼
        src/views.tsx      ← يبني شجرة JSX للصفحة (17 عرضًا)
            │
            ├── يستخدم مكوّنات  src/ui.tsx     (Img, HeroPic, SecHead, CtaBand …)
            ├── يستخدم أيقونات  src/icons.tsx  (SVG سطري، بلا خطوط أيقونات)
            └── يستخدم خرائط    src/imgmap.ts  (مقاسات الصور الحقيقية)
            │
            ▼
        src/layout.tsx     ← الغلاف: <head> كامل + الهيدر + القائمة + الفوتر
            │
            └── يضخّ JSON-LD من  src/ld.ts  (11 بانيًا)
            │
            ▼
        نص HTML جاهز  ──►  المتصفح
                              │
                              ├── public/static/style.css   (CSS واحد، 20 قسمًا)
                              └── public/static/app.js      (11 وحدة، تحسين تدريجي)
```

## 2. لماذا Hono وليس Next.js أو أي إطار عمل؟

| السبب | التفصيل |
|---|---|
| **الموقع تسويقي بحت** | لا لوحة تحكّم، لا تسجيل دخول، لا حالة مستخدم. كل صفحة يمكن توليدها من ثوابت. إطار عمل ضخم يعني تعقيدًا بلا مقابل. |
| **الحافة أولًا** | Hono مكتوب أصلًا لـ Workers. حجم الحزمة النهائية **179 كيلوبايت (52 كيلوبايت مضغوطة)** — رقم لا يمكن الوصول إليه مع Next. |
| **زمن استجابة أوّلي منخفض** | لا ترطيب (hydration)، لا حِزَم React تُنزَّل. المتصفح يستلم HTML مرسومًا ويبدأ الرسم فورًا. |
| **السيو** | كل شيء في HTML الأوّلي. لا يوجد محتوى ينتظر جافاسكربت — وهذا كان شرطًا صريحًا في المشروع (فهرسة كل صفحات المدن كصفحات مستقلة). |
| **قابلية النقل** | التطبيق لا يستخدم أي وحدة من Node. الطلب والاستجابة معياريان (Web `Request`/`Response`)، فينشر على Cloudflare وVercel من نفس الكود. |

### ما الذي تنازلنا عنه مقابل ذلك؟
- لا توجيه على العميل (client-side routing) → كل تنقّل رحلة شبكة كاملة.
  عوّضناها بخط تقدّم علوي (وحدة 4 في `app.js`) وبحجم HTML صغير.
- لا مكوّنات تفاعلية معقّدة → لم نحتج إليها.

## 3. البناء المزدوج: هدف واحد للكود، منصّتان للنشر

الملف `vite.config.ts` يقرأ متغيّر بيئة واحد ويبدّل مُخرِج البناء:

```ts
const target = process.env.BUILD_TARGET ?? 'cloudflare'
plugins: [ target === 'vercel' ? vercel() : cloudflarePages(), … ]
```

| الأمر | المخرَج | المنصّة |
|---|---|---|
| `npm run build` | `dist/_worker.js` + `dist/static/*` | Cloudflare Pages |
| `npm run build:vercel` | `.vercel/output/functions/__hono.func/index.js` | Vercel Edge |

**القاعدة الذهبية التي تحفظ هذا التوافق:**
> لا تستورد أبدًا `fs` / `path` / `crypto` من Node، ولا `@hono/node-server`.
> إذا احتجت ملفًا ثابتًا، ضعه في `public/` — المنصّة تخدمه، لا الكود.

مخالفة هذه القاعدة تكسر أحد الهدفين فورًا وبصمت.

### القاعدة الحاكمة
> **النصوص في `data.ts`/`cities.ts`، والشكل في `views.tsx`، والتنسيق في
> `style.css`.** إذا وجدت نفسك تكتب نصًّا عربيًا داخل `views.tsx` فأنت
> على الطريق الخطأ — ضعه في `data.ts` وحوّله إلى `map()`.

## 5. من 18 معالجًا إلى 76 صفحة

المسارات المعلمَنة (parametrised) تولّد العدد الأكبر من الصفحات:

```
/services/:slug          →  كل خدمة
/occasions/:slug         →  كل مناسبة
/menu/:slug              →  كل فئة تقديمات
/locations/:slug         →  كل مدينة (10)
/:combo{(qahwajiin|sababin-qahwa|diyafa-munasabat)-[a-z]+}
                         →  عائلة كلمة مفتاحية × مدينة  (صفحات هبوط محلّية)
```

المسار الأخير هو **قلب استراتيجية السيو**: `qahwajiin-jeddah` و
`sababin-qahwa-riyadh` … صفحات مستقلّة تمامًا وقابلة للفهرسة، وليست
عناوين URL مزيّفة بمعاملات استعلام. التفصيل الكامل في
[`03-content-model.md`](./03-content-model.md) و[`04-seo.md`](./04-seo.md).

## 6. الجافاسكربت في المتصفح: تحسين تدريجي صرف

`public/static/app.js` — 11 وحدة داخل غلاف واحد:

| # | الوحدة | لو تعطّلت |
|---|---|---|
| 0 | Toast مشترك | لا رسائل تأكيد |
| 1 | هيدر لاصق | الهيدر يبقى ثابتًا |
| 2 | قائمة الجوال السفلية | الروابط موجودة في الفوتر |
| 3 | `reveal()` — `.rv` → `.in` | العناصر تبقى ظاهرة (CSS يضمن ذلك) |
| 4 | خط تقدّم التنقّل | لا شيء يُفقد |
| 5 | ميلان 3D | بطاقات ساكنة |
| 6 | فلترة المعرض | كل الصور ظاهرة |
| 7 | نموذج الحجز → رابط واتساب | الرقم مكتوب نصًّا كذلك |
| 8 | أكورديون الأسئلة | `<details>` أصلي يعمل بلا JS |
| 9 | مشاركة ونسخ | نصوص قابلة للتحديد |
| 10 | الرصيف العائم | القائمة السفلية بديل |
| 11 | إيقاف دوران العملة خارج الشاشة | توفير بطارية فقط |

**لا وحدة واحدة منها ضرورية لقراءة المحتوى أو التواصل مع العميل.** وهذا
مقصود: الهاتف على شبكة ضعيفة يرى موقعًا كاملًا.

> ملاحظة مهمّة: البطل السينمائي في الصفحة الرئيسية **لا يحتاج JS نهائيًا** —
> كل الحركة CSS خالص. انظر [`05-performance.md`](./05-performance.md).

## 2. 🔑 الإخراج الفني للصور — أكبر مكسب أداء وتجربة معًا

### التشخيص الذي غيّر كل شيء

شكوى العميل: **«صورة ما تعرفها شي»** (الصورة غير مفهومة).

الفرضية الأولى الخاطئة: جودة الصورة منخفضة. **الحقيقة:** المشكلة
**نسبة العرض إلى الارتفاع**.

```
صورة 16:9 (1600×893)  داخل إطار هاتف 390×926
      ↓
CSS يغطّي الإطار (object-fit:cover)
      ↓
يبقى شريط رأسي عرضه ≈ 22٪ من الصورة الأصلية
      ↓
الدلّة (موضوع الصورة) تقع خارج هذا الشريط
      ↓
المستخدم يرى ضبابية خلفية فقط
```

### الحل: تركيبان مستقلّان، تنزيل واحد

```tsx
<picture>
  <source media="(max-width:767px)" srcset="…-tall-*.webp" />  {/* 900×1600 */}
  <img src="…-lg.webp" srcset="…" />                            {/* 1600×893 */}
</picture>
```

المتصفح ينزّل **ملفًا واحدًا فقط** — لا عقوبة أداء، بل مكسب: ملف الجوال
الطولي (23ك) أصغر من ملف المكتب العرضي (72ك).

### 🔴 المصيدة: تمهيد LCP يجب أن يُقسَّم بنفس الاستعلام

هذه أهم فقرة تقنية في الملف. لو مهّدنا صورة واحدة:

```html
<!-- ❌ خطأ: الهاتف ينزّل الملف العرضي الذي لن يرسمه أبدًا -->
<link rel="preload" as="image" href="/static/img/hero-royal-md.webp">
```
النتيجة: **تنزيلان** — العرضي (بسبب التمهيد) والطولي (بسبب `<picture>`).
أي عقوبة أداء صافية، وتأخير LCP بدل تحسينه.

الحل في `src/layout.tsx`:
```tsx
hasImg(`${hero}-tall`) ? (
  <>
    <link rel="preload" as="image" media="(max-width:767px)"
      href={imgSrc(`${hero}-tall`)} imagesrcset={imgSet(`${hero}-tall`)}
      imagesizes="100vw" fetchpriority="high" />
    <link rel="preload" as="image" media="(min-width:768px)"
      href={imgSrc(hero)} imagesrcset={imgSet(hero)}
      imagesizes="100vw" fetchpriority="high" />
  </>
) : ( /* تمهيد واحد للصفحات بلا توأم طولي */ )
```

> **القاعدة:** كل `<picture>` بـ `<source media>` يجب أن يقابله تمهيد
> مقسَّم بـ **نفس** استعلام الوسائط حرفيًا. أي اختلاف = تنزيل مزدوج صامت.

## 3. البطل السينمائي — خمس طبقات بتكلفة صفر تخطيط

الطلب: صفحة رئيسية **«فخمة + أنيميشن + لكجري»**.

| # | الطبقة | المدّة | الخاصية المُحرَّكة |
|---|---|---|---|
| 1 | تلاشٍ متقاطع بين صورتين (`crossFade`) | 22 ثانية | `opacity` |
| 2 | Ken Burns على كل صورة (`kenBurnsA/B`) | 26 ثانية | `transform` |
| 3 | شعاع ذهبي عابر (`beam`) | 13 ثانية | `transform` |
| 4 | تدرّج ظهور الأسطر (`riseIn`) | 0.95 ثانية × 7 | `opacity` + `transform` |
| 5 | لمعة ذهبية على العنوان (`sheen`) | 5.6 ثانية × 2 | `background-position` على نص مقصوص |

### 🔴 لماذا هذه الحركات مجّانية فعلًا؟

`transform` و `opacity` **لا تُبطل التخطيط ولا الرسم**. تُنفَّذ على خيط
المُركِّب (compositor thread) في الـ GPU، بمعزل عن الخيط الرئيسي:

- **CLS = 0** (لا إزاحة تخطيط)
- الخيط الرئيسي حرّ تمامًا لاستقبال أول تفاعل (INP)
- **صفر جافاسكربت** — البطل كله CSS

الخاصية الوحيدة الاستثناء هي `background-position` في اللمعة، وهي تعمل
على **عنصر نصّي واحد** بمساحة صغيرة ومرّتين فقط ثم تتوقّف (`2 both`).

### دليل عدم وجود فائض أفقي

```
python3 qa/scripts/cine.py
→ overflowX: 0   على 390×844 (جوال)
→ overflowX: 0   على 1440×900 (مكتب)
→ كل الحركات الخمس مؤكَّدة نشطة
```

هذا الفحص ضروري لأن الطبقات تستخدم `inset:-20% -40%` و `scale(1.16)` —
وهي قيم يمكن أن تُنتج شريط تمرير أفقيًا لو لم تُحصر داخل `overflow:hidden`.

### احترام تفضيل تقليل الحركة

```css
@media (prefers-reduced-motion: reduce){
  .hero-cine .hero-bg img, .hero-cine .hero-bg-2, .hero-cine .hero-bg-2 img,
  .hero-shine, .hero-ttl .shimmer, .hero-cascade > * { animation: none }
  .hero-shine { display: none }
  .hero-ttl .shimmer { -webkit-text-fill-color: var(--gold-lite); color: var(--gold-lite) }
}
```
النتيجة: إطار ثابت واحد، بلا انزلاق ولا لمعة ولا تدرّج — والعنوان يعود
لونًا صريحًا (لأن النص المقصوص بلا حركة يبقى شفافًا = غير مرئي).

### 🔴 حاجز تقني: الحجاب المُعتِم لا يمكن أن يكون `::after` لصورة

الحجاب يجب أن يعلو **كلتا** الصورتين. لو كان `::after` لإحداهما لظهر تحت
الأخرى أثناء التلاشي. لذلك صُنع طبقة مستقلّة:
```css
.hero-cine .hero-bg::after { display: none }  /* أُبطلت */
.hero-cine .hero-veil { position:absolute; inset:0; z-index:1 }
```
ترتيب الطبقات: صورة (0) → حجاب (1) → شعاع (2) → نص (3).

## 4. 🔴 `box-shadow` مقابل العناصر الوهمية — درس مُكلِف تعلّمناه مرتين

عند بناء هالة ذهبية حول زر:

| الطريقة | فائض تمرير؟ |
|---|---|
| `box-shadow: 0 0 28px rgba(...)` | **لا** — يُرسم خارج الصندوق دون مساهمة في `scrollWidth` |
| `::after { transform: scale(1.4) }` | **نعم** |
| `::before { inset: -5px -2px }` | **نعم** |

الحالة الثانية حدثت حرفيًا: أردنا توسيع منطقة اللمس لأزرار القائمة إلى
44 بكسل بدون تكبير الشكل، فأضفنا `::before` بـ inset سالب. النتيجة
المقيسة: **من 0 عنصر مقطوع إلى 2 عنصر مقطوع.** أُلغيت الفكرة.

> **القاعدة:** لكل تأثير يمتدّ خارج حدود العنصر، استخدم `box-shadow`
> (أو `filter: drop-shadow`) — لا عنصرًا وهميًا بأبعاد سالبة.

## 5. خطّ أنابيب الصور

```
صورة PNG مولّدة (1–1.3 ميجابايت)
      ↓ تحويل إلى WebP بثلاثة مقاسات
sm  (شاشات صغيرة)  ·  md (متوسطة)  ·  lg (كبيرة)
      ↓ تسجيل في src/imgmap.ts مع المقاسات الحقيقية
"hero-royal":      [["sm","md","lg"], 1600, 893]
"hero-royal-tall": [["sm","md"],       900, 1600]
```

**لماذا تُسجَّل المقاسات في الكود؟**
لأن `width`/`height` على `<img>` **إلزاميان** لمنع إزاحة التخطيط. لو
اعتمدنا على المتصفح ليكتشف المقاس بعد التنزيل، فكل صورة تسبب CLS.
`imgmap.ts` يجعل الرقم الصحيح مستحيلًا نسيانه.

الصور الطولية لها مقاسان فقط (`sm`, `md`) — لأنها لا تُعرَض إلا على شاشات
أقل من 768 بكسل، فمقاس `lg` سيكون هدرًا صافيًا.

## 6. التخزين المؤقّت والترويسات

```json
// vercel.json
"/static/(.*)" → "Cache-Control: public, max-age=31536000, immutable"
"/(.*)"        → X-Content-Type-Options: nosniff
                 Referrer-Policy: strict-origin-when-cross-origin
                 X-Frame-Options: SAMEORIGIN
                 Permissions-Policy: geolocation=(), microphone=(), camera=()
```
`immutable` آمن لأن أسماء الصور ثابتة والـ CSS/JS يحملان معامل إصدار `?v=`.

الخطوط: `preconnect` إلى `fonts.googleapis.com` و`fonts.gstatic.com`، ثم
**طلب واحد** يجمع Amiri + Tajawal مع `display=swap`.
